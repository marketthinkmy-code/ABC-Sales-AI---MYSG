**適用**:`AI 回覆 幫你獲客` (1984262458861966, TWD) —— 此帳號 MCP 未開放,
但 Meta 後台的「自動化規則」對它完全可用。**零程式、零月費、今天就能上。**

把 Soo Cheng 的 kill/scale 邏輯,翻譯成 Ads Manager 能設的規則。

## 先定一個數字:你的目標 CPL

Soo Cheng 用 MYR,你這帳號是 TWD 且是「AI 回覆獲客」漏斗(可能是 Messenger/名單,
不是 webinar 報名),CPL 基準不一樣。**先填你自己的目標每次成果成本**:

```
目標 CPL = NT$______   (你願意付多少錢換一個 lead/回覆)
```
下面規則的門檻都用這個數字算。若還不知道,先跑 3–5 天看實際 CPL,取中位數當目標。

## 4 條規則(Ads Manager → 自動化規則 → 建立規則)

### 🔴 規則 A — 關掉燒錢零成果(對應 Soo Cheng「零轉換就關」)
- **套用對象**:所有進行中的廣告組合
- **動作**:關閉廣告組合
- **條件**:
  - 成果數量 = 0
  - 且 花費 ≥ `2 × 目標CPL`
- **時間範圍**:過去 3 天
- **檢查頻率**:每天(持續)

### 🔴 規則 B — 關掉 CPL 過高(對應 Soo Cheng 60+ 全關)
- **動作**:關閉廣告組合
- **條件**:
  - 每次成果成本 > `1.7 × 目標CPL`
  - 且 花費 ≥ `1 × 目標CPL`(確保有足夠數據才判死)
- **時間範圍**:過去 3 天
- **頻率**:每天

### 🟢 規則 C — 加碼 winner(對應 Soo Cheng CPL<35 就加預算)
- **動作**:調高每日預算 —— 提高 20%
- **條件**:
  - 每次成果成本 < `1 × 目標CPL`
  - 且 花費 ≥ `3 × 目標CPL`(跑出量才加)
- **上限**:設每日預算上限(對齊 Soo Cheng 邏輯,例如 `10 × 目標CPL`)
- **時間範圍**:過去 3 天
- **頻率**:每天最多一次(避免一直重進學習期)

### 🟢 規則 D — 極佳者通知你複製(native 不能自動複製)
- **動作**:傳送通知(不自動執行)
- **條件**:每次成果成本 < `0.7 × 目標CPL` 且 成果數量 ≥ 5
- **收到通知後**:手動複製那個廣告組合到新受眾放大。
  > ⚠️ 「自動複製贏家」是 native 規則做不到的一環 —— 這正是 Path B(API)才有的能力。

---

## 這樣能做到 Soo Cheng 幾成?

| 能力 | Native Rules | 缺口 |
|---|---|---|
| 自動關 loser | ✅ | — |
| 自動加碼 winner | ✅ | — |
| 自動複製贏家 | ❌ 只能通知 | 要 API |
| **自動上新廣告** | ❌ | 要 API 或手動 |

→ **「自動跑」約 80% 做得到,零成本今天上。**
→ **「自動上」native 做不到**,要嘛手動建、要嘛走 Path B(API)。

## 設定後
- 前 1 週每天看規則有沒有誤殺(Meta 規則有「活動記錄」可查它做了什麼)。
- CPL 目標隨 offer 調整,只改規則裡的數字。
- 想補上「自動上 + 自動複製贏家」→ 看 `api-engine/README.md`(Path B)。
